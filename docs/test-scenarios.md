# Тестовые сценарии

Сценарии T1–T13 — из аналитики проекта. Здесь показано, как каждый из них проверяется в прототипе и какой результат ожидается.

## Как запускать проверки

| Проверка | Что покрывает | Команда |
|---|---|---|
| Модульные тесты | скоринг и решение — 17 тестов; таблица переходов статусов, список обязательных документов, формат ошибок — 18 тестов | `pnpm test` |
| Smoke | 7 демо-компаний: от заявки до решения, одобренные заявки — до выдачи денег | `node scripts/smoke.mjs` |
| Postman | сценарии T1–T13 по шагам: 79 запросов, 132 проверки ответов | `npx -y newman@6.2.1 run docs/postman/alfa-smart-credit.postman_collection.json` |
| CI | на каждый PR: lint и модульные тесты, а отдельной задачей — сборка Docker-образов API и заглушки, smoke и Postman | GitHub Actions, файл `.github/workflows/ci.yml` |

Через интерфейс те же сценарии (T1, T2, T3, T5, T6, T7, T8, T11) проходятся по шагам из [demo.md](demo.md): кабинет клиента и кабинет аналитика работают на том же API.

Для smoke и Postman API и заглушка должны быть запущены, например `docker compose up --build postgres mock-external api`. Обе проверки создают новые заявки, поэтому их можно запускать повторно на той же базе.

### Postman вручную

1. Импортируйте `docs/postman/alfa-smart-credit.postman_collection.json`.
2. В настройках Postman укажите корень репозитория рабочей папкой (Settings → General → Working directory). Иначе Postman не найдёт PDF для загрузки из `docs/postman/files`.
3. Запустите коллекцию целиком через Run collection. Папки идут по порядку, первой должна выполниться «0. Вход»: она сохраняет токены всех пользователей.

Запросы «Ждём решения» повторяются раз в секунду, пока конвейер обрабатывает заявку. Повтор работает только при запуске через Run collection или newman. Если отправлять запрос кнопкой Send, жмите её несколько раз.

## T9 — сбой внешнего сервиса, ручная проверка

Чтобы проверить этот сценарий, нужно остановить контейнер, поэтому в Postman его нет.

```bash
docker compose stop mock-external
# подайте заявку igor за «Северный склад» — в кабинете или через Postman (папки «0. Вход» и T1 до шага «Ждём решения»)
docker compose start mock-external
```

Ожидаемый результат:
- клиент получает ответ на отправку сразу, а заявка уходит в фон;
- API ждёт ответа внешнего сервиса до 3 секунд и делает одну повторную попытку, затем заявка переходит ENRICHMENT → MANUAL_REVIEW с причиной «Не удалось получить данные из внешних источников — заявку посмотрит специалист»;
- клиент видит «Заявку рассматривает специалист»;
- в карточке аналитика проверки реестра, ФНС и БКИ отмечены `ok: false`, скоринга нет — решение принимает аналитик.

Поиск компании по ИНН `0000000000` (`GET /registry/lookup?inn=0000000000`) имитирует недоступный реестр и при работающей заглушке: ответ 503 `SERVICE_UNAVAILABLE`. Неизвестный ИНН → 404 и предложение заполнить данные вручную.
