# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого бизнеса. Хакатон Альфа-Банка 2026.

Предприниматель подбирает продукт, подаёт заявку и в реальном времени видит, на каком она этапе. Конвейер сам проверяет документы, запрашивает реестр, ФНС и БКИ, считает скоринг и принимает решение: одобрение, контрпредложение, ручное рассмотрение или отказ. Решение объясняется простыми словами, с подсказками, что сделать, чтобы условия стали лучше. Если не хватает документа, банк запрашивает его прямо в кабинете, и после загрузки заявка продолжается сама. Договор подписывается кодом из кабинета, после подписи деньги выдаются.

У аналитика банка свой кабинет: очередь заявок на ручное рассмотрение, карточка со всеми данными и баллами скоринга, решение с обязательным комментарием, запрос документа у клиента.

## Быстрый запуск

Нужен только Docker.

```bash
docker compose up --build
```

| Что | Адрес |
|---|---|
| Кабинет клиента и аналитика | http://localhost:8080 |
| API | http://localhost:3000/api/v1 (проверка: `/api/v1/health`) |
| Заглушка внешних систем | http://localhost:4001 |

Файл `.env` не нужен: у всех переменных есть значения по умолчанию в `docker-compose.yml`, а `.env.example` показывает, что можно поменять. При старте API сам применяет миграции и загружает демо-данные; повторный запуск ничего не дублирует. Начать с чистой базы: `docker compose down -v`.

Запустить только бэкенд, без фронтенда:

```bash
docker compose up --build postgres mock-external api
```

## Локальная разработка

Нужны Node.js 24 и pnpm 10 (`corepack enable`). Базу удобно поднять из Docker Compose.

```bash
corepack enable
pnpm install
docker compose up -d postgres                     # PostgreSQL на localhost:55432
```

Создайте `apps/api/.env.local` (он в `.gitignore`):

```
DATABASE_URL=postgresql://alfa:alfa@localhost:55432/credit
MOCK_EXTERNAL_URL=http://127.0.0.1:4001
JWT_SECRET=dev-secret
```

Затем в двух терминалах:

```bash
pnpm --filter mock-external start                 # заглушка на :4001

pnpm --filter @alfa/scoring build && pnpm --filter api build
pnpm --filter api db:migrate && pnpm --filter api db:seed
pnpm --filter api start:local                     # API на :3000
```

Фронтенд — см. [`apps/web/README.md`](apps/web/README.md).

## Архитектурные решения

- **Монорепозиторий (pnpm workspaces).** Фронтенд, API, заглушка и скоринг в одном репозитории, с общей версией зависимостей и одним CI.
- **Скоринг — отдельный пакет `@alfa/scoring`.** Без базы и сети: чистые функции, покрытые тестами на демо-компаниях. Решение воспроизводимо, в каждом результате записана версия правил. Объяснение клиенту строится из тех же данных, что видел скоринг, поэтому всегда совпадает с решением.
- **Одна точка смены статуса.** Любой переход проверяется по таблице переходов. Защита от одновременных изменений и запись в историю идут в одной транзакции. Недопустимый переход — ошибка `409 INVALID_TRANSITION`.
- **Конвейер продолжает работу после перезапуска.** Он смотрит на текущий статус заявки и делает следующий шаг, поэтому после рестарта API заявки продолжаются с того же этапа.
- **Внешние системы — отдельный сервис `mock-external`.** Реестр, ФНС, БКИ, подписание и выдача. API обращается к ним через общий клиент с таймаутом и повтором; если сервис не ответил, заявка уходит специалисту, а не теряется. Для перехода на реальные интеграции меняется только этот клиент.
- **Единый формат ошибок** `{ code, message, details }`, сообщения для пользователя — на русском.
- **Drizzle ORM.** Чистый TypeScript без бинарных движков: проект надёжно собирается в Docker даже при нестабильной сети.
- **Суммы в копейках (целые числа).** Нет ошибок округления, как у чисел с плавающей точкой.

## Что смоделировано и ограничения

- Все внешние системы банка заменены заглушкой с синтетическими данными. Код подписи по условиям кейса показывается прямо в кабинете, без СМС.
- Модели ИИ не используются: решение принимают детерминированные правила.
- Истечение срока (EXPIRED) заложено в модель статусов, но автоматического таймера в прототипе нет.
- Конвейер работает внутри процесса API, без отдельной очереди задач. Для прототипа этого достаточно; в промышленной версии этапы выносятся в очередь.
- Документы (PDF, JPG, PNG до 10 МБ) хранятся в базе.
- Сообщения об ошибках валидации отдельных полей (`details`) — на английском, от class-validator; общий текст ошибки (`message`) — на русском.
